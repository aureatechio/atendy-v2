- [Módulo /clientes (CRM core)](clientes-module.md) — core do CRM: listagem com filtros, kanban drag-and-drop, detalhe com 6 cards (info, histórico, comentários, tarefas, reuniões, ajustes). Server actions: `addComment`, `changeStage`, `setArchived`. Build de dados em `buildClientesData` (puro).
- [Módulo /funil (Pipeline visual)](funil-module.md) — visão de processo do pipeline (V2 padrão, V1 vista detalhada). Usa as mesmas tabelas que `/clientes` mas com lente de SLA/rows-por-task. Sempre excluí arquivados. `buildFunilData` é puro.
- [Subsystem `client_pipeline_stages`](pipeline-stages.md) — etapas do funil: schema, hierarquia 2 níveis (root → sub), regras de SLA, APIs admin (CRUD + reorder + migrate + impact), consumidores e padrão de ordenação topológica.
- [Tabela `production_tasks`](production-tasks.md) — schema da tabela de tarefas, constante `COMPLETED_TASK_STATUS = "concluido"`, 9 consumidores transversais (lista, detalhe, funil, alertas, cron, admin migrate). Não há rota dedicada.
- [Sistema de alertas](alerts-system.md) — alertas unificados (`stage_sla` + `task_overdue` + `followup`): cron, evaluators puros, `diffAlerts`, tabela `sla_alerts`, endpoint `/api/alerts`. View `cliente_last_interaction` alimenta followup.
- [Sistema de auth](auth-system.md) — Supabase Auth + `profiles` + capabilities. `AuthSnapshot` canonical, `getAuthSnapshot` cacheado, guards (`canAccessCS`/`canAccessAdmin`), `requireAdminAccess` para actions/APIs. 7 roles, débitos do refactor em `docs/role-system-cleanup-debts.md`.
- [SLA e feriados](sla-holidays.md) — `calculateSlaDeadline` + `evaluateSla`, unidades (`business_days` default, `calendar_hours`, `business_hours` ❌ não implementado), timezone BRT fixo, tabela `business_holidays`.
- [Módulo /cs (Customer Success)](cs-module.md) — área restrita de gestão CS: hub, força-tarefa de redistribuição em massa, compras pagas. Guard `canAccessCS` (admin/dev/cs_head).
